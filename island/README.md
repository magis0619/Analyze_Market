# 島歩き（仮）

綺麗な海に囲まれた島を歩くだけの three.js 製の小品。ゴールも競争もない。
DELVERS（このリポジトリのルート）とは別アプリで、vite の root ごと分けてある。

```bash
npm run island:dev      # http://localhost:5174
npm run island:build    # 型検査 + ビルド（dist-island/）
npm run island:shots    # 画面を一式撮る（要 dev サーバ）
npm run island:critique # 参考画像との色の突き合わせ（要 dev サーバ）
```

URL パラメータ:

| パラメータ | 意味 |
|---|---|
| `view` | `beach` / `overlook` / `shallows` / `reef` と、自己批評用の `rest` / `palms` / `adan` / `deigo` / `mangrove` / `pier` / `lineup` / `campfire` / `villa` / `bedroom` / `living` / `veranda`。既定は `bedroom`（寝室から始まる） |
| `time` | 0〜24 の時刻 |
| `weather` | 0（快晴）〜1（曇天） |
| `still` | 波と雲の時刻を固定する（スクリーンショットの再現性用） |
| `hud` | `0` で操作パネルを隠す |
| `arrive` | 到着の度合いを 0〜1 で固定する（演出の途中を撮るため） |
| `lineup` | `1` で、種を1体ずつ並べただけの検分用シーンにする |

操作は WASD / 矢印キーで歩き、ドラッグで見回す。`H` でパネルの開閉。
スマホは画面左側のドラッグで移動、右側のドラッグで視点。

## 構成

```
island/src/
  heightfield.ts  湾の地形（4層の高さレイヤーと2つの岬）を CPU で焼く
  terrain.ts      焼いた高さ場 → メッシュ + 水が参照する深度テクスチャ
  water.ts        深度ベースの水シェーダ（吸光・散乱・Gerstner波・泡）
  sky.ts          手続き生成のスカイドームと星
  meshbuild.ts    手続きジオメトリの組み立て（筒・リボン・塊・箱）
  flora.ts        種ごとの植生ジオメトリ（ヤシ／アダン／デイゴ／月桃／
                  マングローブ／ソテツ／花木／汎用の低木と木）
  structures.ts   東屋・ハンモック・桟橋・灯台・琉球石灰岩の石垣・焚き火の
                  常設物（薪山・囲みの岩・焦げ跡）
  campfire.ts     焚き火の動的な部分（炎3層・火の粉・消えかけの煙・光）
  villa.ts        別荘（外観・庭とプール・室内家具・歩ける2階建て・
                  到着/別れの動線・スライドドア・プール水シェーダ）
  collision.ts    別荘の壁・家具・ドアの水平方向の当たり判定（AABB）
  foliage.ts      どの種をどこに撒くかと、共通マテリアル
  textures.ts     琉球石灰岩のアルベド／法線マップをその場で焼く
  env.ts          時刻・天候・到着度・焚き火の強さと、全マテリアルが
                  共有するユニフォーム
  walker.ts       歩行カメラと決め打ちの視点
  glsl/           空・深度サンプリングの共通シェーダチャンク
```

外部アセットはひとつも持たない。岩肌のテクスチャも星も地形も、
すべてシード付きの決定論ノイズからその場で生成している。

## 見た目をどう決めたか

指示書の「参考画像に一致させる」を目分量でやらないために、
**画面を縦20帯に割って帯ごとの平均色を出し、参考画像の実測値と突き合わせる**
方法を採った（`scripts/critique.mjs`）。数値で外れているところだけを直す。

主要な色は sRGB の16進で決めてシェーダ内で線形に直している
（`sRGB()`）。トーンマッピングは `NoToneMapping`。
指定した色がそのまま画面に出ないと、突き合わせが意味を持たなくなるため。

### 水（指示書 §2）

海面の色は「海底までの深さ」ひとつから導いている。

```
body = 海底の色 × exp(-吸光係数 × 光路)      … 透過して見える砂・珊瑚
     + 散乱係数/(2×吸光) × (1 - exp(-2×吸光×深さ))  … 水そのものの色
```

赤がいちばん早く失われるので、浅い＝白砂の色、深い＝ターコイズ、
さらに深い＝紺、という参考画像どおりのグラデーションが自動的に出る。
吸光・散乱の係数は、参考画像の帯ごとの実測色から逆算した値を使っている。

水面の映り込みは素の Fresnel をそのまま使うと、斜めから見た浅瀬が
一面の空色になってしまう。参考画像はいずれも PL フィルタ越しの写真で
反射が大きく削られている（だから珊瑚が透けて見える）ので、
手前ほど反射率を落とし、水平線に近づくほど本来の値に戻している。

### 地形（指示書 §1）

放射ノイズだけでは入り江の抱擁感が出ないため、2つの岬をスパイン
（制御点の折れ線）で明示的に置き、その間を遠浅の水域にしている。
海底は3段構え。汀線の2mはごく浅く（寄せ波が砂の上を走る余地）、
そこから15mほどは浜の急な面、その先が遠浅の棚。
砂を離れるとすぐターコイズが濃くなり、かつ湾いっぱいが明るい、
という参考画像の両方を満たすための形。

### 空（指示書 §3）

密度勾配（地平線ほど大気が厚い）・光度勾配（太陽方向への近さ)・
トワイライト（その積）の3つを掛け合わせる。時刻 0〜24 のパラメータ
ひとつで夜明けから夜まで回る。同じ関数を水面の反射と大気遠近でも
使うので、水平線が破綻しない。

夜は主光源が太陽から月に切り替わる（`uKeyDir` / `uKeyLight`）。

### 天候

個別のシステムは作らず、彩度を落とす・フォグ密度を上げる・
雲量を上げる・太陽の光度を弱める、の4つだけ（指示書 §3 の方針）。

### 到着と、帰り道（想定プレイヤー像）

指示書の「仕事に疲れて南国に行っている人」という前提を、雰囲気ではなく
判断基準として扱っている。

- **到着の演出** — 起動直後は彩度を落とした青灰色（オフィスの残響）から
  始まり、6.5 秒かけて光と彩度が満ちる。`uArrive` ひとつを全マテリアルの
  `grade()` に通しているだけなので、あとから足した要素も自動でこの演出に乗る。
- **終わり方** — タブを離れる／ウィンドウのフォーカスが外れると、
  2.8 秒かけて静かに彩度が引く。戻ればまた満ちる。「行って、帰ってくる」
  をひとつの体験にするため、帰り道のほうを少し速くしてある。
- **数字を見せない** — 時刻は `11:30` ではなく「真昼」「夕焼け」と出す。
  スコアもカウンターも進捗率も無い。到着度も内部の値のままで UI には出さない。
- **急かさない** — タイマー・通知・誘導は一切無い。何もしなくても何も減らない。

### 植生と人工物（指示書 §4-1）

種ごとにシルエットが違うことが大事なので、汎用の「木」を色替えするのでは
なく、それぞれの特徴を形で作っている。置き場所も表のとおりに分けた。

| 種 | 形の要点 | 置き場所 |
|---|---|---|
| ヤシ | しなる幹と、垂れる羽状葉。variant 3種で幹の曲がりと垂れ方を変える | 砂浜沿い（汀線から 5〜38m） |
| アダン | 放射状の太い帯状葉と、幹から地面へ降りる気根 | 岬の岩場のふち（傾斜 0.22 以上） |
| デイゴ | 広く張った枝先に、真っ赤な房 | 岬に2本だけ |
| 月桃 | 笹に似た幅の広い葉の株と、垂れ下がる白〜桃の花穂 | 東屋の足元 |
| マングローブ | 絡み合って水面から突き出す支柱根 | 湾の奥、波の当たらない浅い隅 |
| ソテツ | 葉痕の残る太い幹に、垂れない硬い羽状葉 | 東屋・桟橋まわり |
| ハイビスカス／ブーゲンビリア | 葉の面より外に出した花 | 東屋・桟橋まわり |

人工物は東屋・ハンモック・桟橋・灯台・石垣。数は少なく、
「人の手が入った気配」だけを置いている。

羽状葉（ヤシとソテツ）は同じ関数で作っていて、芯まわりの角度 `phi` を
大きくすると垂れてヤシに、小さいままだと硬く跳ねてソテツになる。

見比べは `?lineup=1` が早い。種を1体ずつ砂の上に並べたシーンになる。

### 焚き火（指示書 §5）

東屋のそばに常設し、「留まる」場所の中心にしている。時刻を直接 if で
判定するのではなく、§3 のスカイボックスで使っている光度パラメータ
（`env.uniforms.uDay`）と連動させた `duskFactor = 1 - uDay` で強さを決める。
空が暗くなるほど火が自然に強まり、夜明けとともに弱まりながら消えていく
（`env.ts` の `update()` を参照）。

薪山・囲みの岩・焦げ跡（`structures.ts` の `firePit()`）は常設の静的
ジオメトリで、昼間は火が点いていないただの薪の山として見える。炎・火の
粉・煙・光（`campfire.ts`）はそこに重ねる動的な部分で、`uFireGlow` 一つを
見ていれば済むようにしてある。

- **炎** — 指示書の表のとおり Core／Mid／Outer の3層。芯ほど低く・明るく・
  揺れない。Outer層だけノイズを足して、先端がちらつくようにしている。
- **火の粉** — 18粒。個々に独立した周期を持たせ、周期の前半だけ立ち上って
  後半は次を待つ形にすることで「たまに1粒跳ねる」疎さを出している。
- **消えかけの煙** — 普段はほぼ見えない。夜明け側の遷移でだけ強調する
  （`uSmokeGlow`）。太陽高度の式は H=0（正午）を境に、H<0（午前）だけが
  「上り」なので、微分せずに `-sin(H)` の符号だけで求まる。曇天寄りに
  弱まっていく夕方側では煙を出さない、という非対称を狙った。
- **周囲への波及光** — 指示書は `PointLight` を挙げているが、この作品の
  地形・水・植生はどれも three.js のシーンライトを参照しない自前の
  ShaderMaterial なので、実体の `THREE.PointLight` は置いてあるものの
  現状どの見た目にも寄与しない。実際に砂や葉が暖色で照らされる効果は
  `uFireBounce` という共有ユニフォームを terrain / foliage 側で加算する
  形で作っている（この作品の照明モデルに素直に乗せた形）。

批評用の視点は `?view=campfire`。`?view=lineup` と同様、時刻を変えて
夜（強く灯る）と昼（ただの薪山）の両方を確認する。

焚き火から半径 3.6m は月桃・ソテツ・花木を生やさない。囲んで座る場所に
藪が生えていては「留まる」場所にならないため（`FIRE_CLEAR_R`）。

### 別荘（指示書 §6）

「到着/別れの演出」を彩度の変化という抽象処理のままにせず、この家から
出発しこの家に戻るという具体的な動線として実体化した（`villa.ts`）。
拾った貝殻・流木を飾る場所という位置づけでもあるが、飾り棚・書き物机の
実際の連動（アイテム表示）は指示書の導入順どおり後回しにしてある。

- **敷地** — 砂浜からやや高台寄り、湾を見渡せる場所（東屋・焚き火からは
  見える距離感、近すぎない位置）。**モダンミニマル**の2階建て（当初の
  地中海〜南欧リゾート風は撤回した）。白い立方体ボリューム、フラットな
  屋根、床から天井までのガラス面、木目調のウッドデッキ、装飾を最小限に
  留めるほどこのスタイルらしくなる。
- **外観** — 庭・プール・ウッドデッキ、ガラスの腰壁とスチールの手すり、
  玄関先の鉢植え（ソテツ1本だけ）、軒下の間接照明（夜だけ静かに灯る。
  焚き火のような揺らぎは持たせない単純な発光）。傾斜地なので、建物本体も
  プールデッキも「4隅のうち最も高い点に合わせて基礎の袴で吸収する」と
  いう東屋で使った手法をそのまま踏襲している。1F 南面は隅の方立だけを
  構造壁として残し、あとは固定ガラス2枚＋中央のスライドドアで床から
  天井までのガラス面にした。2F も南・西を大きなガラス面にしている。
- **室内** — 1F は玄関とリビングをひと続きの土間にして、ソファ・TV・
  キッチン・飾り棚・螺旋階段を置いた開放的な作り。2F は寝室で、
  ベッドと書き物机、大きな窓。螺旋階段の物理的な段差判定は最低限に留め、
  踊り場の中を対角に上る単純なスロープとして扱う（`VillaFloorTracker`）。
- **歩ける2階建て** — 1F・2F は同じ footprint を積み重ねているだけなので、
  `(x, z)` だけではどちらの階にいるか決まらない。`VillaFloorTracker` が
  「いまどちらの階にいたか」を覚えておき、階段の踊り場を通過したときだけ
  高さを切り替える。`Walker` はこれを地形の高さ場より優先する
  `groundOverride` として受け取る。
- **壁・ガラスの明るさ** — 真の物理陰影（法線と光源のなす角がゼロ付近で
  真っ暗）のままだと、日陰側の壁やガラスが時刻によって黒い板に見えてしまう。
  焚き火の煙と同じ発想で、既存の `leaf` パラメータ（本来は「どれだけ硬い
  影を許すか」の汎用ノブ）を流用し、壁面とガラス面に常時明るさの底上げを
  かけている（`WALL_LIT = 0.62`）。それでも直射を受けない面は控えめな
  明るさに留まる — 参考画像にも見られる、日陰側が濃色ガラスに沈む
  実在のモダン建築と同じ振る舞いで、これは意図した結果。

### 家の中の修正（実装レベルの追加指示）

- **家の衝突判定** — 元々この作品の移動は「地形の高さ場に足元を合わせる」
  だけで、壁という概念自体が無かった（歩けば壁をすり抜けた）。垂直方向
  （どの階にいるか・階段の高さ）は `VillaFloorTracker` が既に解決して
  いるので、新設の `collision.ts` では水平方向の押し返しだけを足す。
  壁・ソファ・キッチンカウンター・ベッドの静的 AABB と、スライドドアの
  動的 AABB を持ち、x → z の順に軸ごとに分離して判定することで壁沿いに
  スライドできるようにしている（指示書のコード例と同じ考え方）。指示書の
  `STEP_OFFSET` によるよじ登り判定は採用していない — 階段は既にスロープ
  として歩けるので、ここで重ねると二重になるため。
- **プールの水質** — 「海と同等にする」を、独自の色を作り込むのではなく
  海の水シェーダ（`water.ts`）が使っている `uExtinction` / `uScatterCoef` /
  `uKeyLight` / `uAmbLight` / `uSunColor` をそのまま共有する形で実現した
  （`createPoolWater`）。プールは一定の浅い水深とタイルのアルベドを仮定
  するだけで、あとは海とまったく同じ吸光・散乱の式に乗る。小さな波紋と
  空の映り込みも足している。
- **螺旋階段** — 白/スチールの片持ち踏板が浮いているように見せている
  （`buildSpiralStair`）。実際の段差判定は上記のとおり `VillaFloorTracker`
  のスロープに任せ、見た目だけをモダンに寄せた。
- **スライド式ガラスドア** — この作品の家具・地形はすべて静的に焼き込んだ
  merged geometry で、動くものは焚き火・軒灯だけが例外だった。ドアも
  同じ扱いにして、独立した `THREE.Mesh` としてプレイヤーの位置を毎フレーム
  見て開閉し、当たり判定（AABB）もその開閉に追従させている
  （`createSlidingDoor`）。開いても閉じてもガラスなので常に半透明——
  「閉じている＝不透明」ではなく「閉じている＝通れない」という区別に
  した。
- **ソファ・TV** — ソファは座面・背もたれ・肘掛けの継ぎ目に丸みを通して
  柔らかく見せている。TV は「視距離4.5mから対角約50インチ相当」という
  指示書の計算式に合わせて拡大した。

到着/別れの動線は `arrivalDepth()` が担う。寝室にいるあいだは
`env.arriveTarget` を 0.05（仄暗い、彩度の低い「目覚め」）に、階段を
降りるほど 0.45 へ、フレンチドアを抜けて庭・プールを横切るほど
1.0（浜と同じ満ちた色）へ滑らかに近づける。逆順で戻れば同じ曲線を
逆にたどる。実際の変化は `env.ts` の ease（6.5秒で満ち／2.8秒で引く）に
そのまま乗せているので、位置が飛んでも急変はしない。タブを離れた
ときは、いまどこにいてもこの位置ベースの目標値より優先して 0 へ引く
（終わり方の安全弁は変えていない）。起動時の既定視点も `beach` から
寝室（`?view=bedroom`）に変え、「目覚めて、歩いて出ていく」を最初の
体験にした。

批評用の視点は `?view=villa`（外観）・`?view=bedroom`（寝室）・
`?view=living`（リビング、フレンチドア越しに庭と湾）・`?view=veranda`
（ベランダからの見晴らし）。`arrive` パラメータで演出の途中を固定できる
（例: `?view=living&arrive=0.45`）。

## 残っている差

`npm run island:critique`（砂浜視点・11:30・快晴）の実測:

| 領域 | 平均色差 |
|---|---|
| 空 | 16.3 |
| 海 | 31.0 |
| 砂浜 | 18.4 |
| 全体 | 21.2 |

残っている差は主に2か所。

- **水平線ぎわ（画面 40〜45%）** — 参考画像はここに巻雲が横切っていて、
  雲量ひとつでは同じ位置に同じ雲を置けない。
- **汀線から数 m（画面 60〜70%）** — 参考画像のこの位置の色は水深 1m 相当だが、
  目線 1.7m から見るとその画面位置は汀線の 1〜4m 沖にあたる。
  そこに水深 1m を持たせるには汀線を崖にするしかなく、寄せ波が
  砂を走る余地が無くなる。ここは physically ありえる形のほうを採った。

なお、赤の吸光係数は実際の海水（0.45/m 程度）よりかなり大きい値を使っている。
参考画像はいずれも彩度を上げた写真で、浅瀬から赤が完全に抜けているため。

## 次にやること（指示書 §6 の続き）

波が足跡を消す／漂着物拾い／瓶に手紙を流す／潮の満ち引きで現れる道。
足跡と漂着物は、すでにある「寄せ波の水面高さ」（`swash()`）と
深度テクスチャの上に乗せられる。線香花火は、火が灯っている間（`uFireGlow`
が高い間）だけ焚き火のそばで使える小道具として自然に繋げられる。

別荘の飾り棚・書き物机は、いまは形だけの家具（`buildInterior1F` /
