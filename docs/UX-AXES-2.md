## 実装で分かったこと

### 通知には欠陥が3つあった（軸C）

「機能していないかも」というご指摘は正しかった。しかも1つではなかった。

1. **`trigger: nil` で作っていた。** あれは「今すぐ配信」の意味で、帰還時刻の指定ではない。
2. **帰還した瞬間に鳴らそうとしていた。** その処理はアプリが動いている `tick()` の
   中でしか走らない。つまり**閉じている間は永久に鳴らない**——
   放置ゲームで通知が要るのは、まさに閉じている時なのに。
3. **前景では既定で消音される。** Apple の文書に
   「The system silences notifications for foreground apps by default」とある。
   `willPresent` の delegate を置かないと出ない。

→ 出発の瞬間に `UNTimeIntervalNotificationTrigger` で予約し、
帰還時は鳴らすのではなく**予約を取り消す**。許可の有無は毎回 OS に訊く
（前は非同期で入る `granted` を持っていて、入る前に呼ばれると黙って捨てていた）。

### 「押せる」を測っていたが、押していなかった

ご報告の2件は**どちらも既存の検査を通っていた**。

- **文字の上しか反応しない。** `.background` は絵を敷くだけで**当たり判定を広げない**。
  枠は 44pt あるので A3 は通る。XCUITest のタップも要素の中央＝文字の上に落ちるので通る。
- **深いダンジョンが選べない。** 地図のノードが板より下にあり、`ScrollView` が
  タップを飲んでいた。`isHittable` は要素自身の可視性しか見ないので 10個とも「押せる」。
  経路は奥へ向かって下へ降りるので、**深いものだけ**板の下に入る。
  拠点のチップで一度直した穴を、地図でもう一度踏んでいた。

→ **寸法を測るのをやめて、押して、変わったかを見る**検査を2つ足した。

### 変異で、検査のほうの間違いも分かった

「枠の端を押す」検査を `cta` に当てて変異させたら、**捕まらなかった**。
`TierButton` は塗りつぶした背景を持つので、`contentShape` が無くても押せる。
この欠陥が出るのは**背景を持たないボタン**（文字と記号しか描かれていないもの）だけ。
検査の当て先を「詳細」（全幅・背景なし）に変え直した。

**変異を当てなければ、当て先が間違っていることに気づかなかった。**

**94 / 100**

### B で2点引いた理由

出典は「1分未満は％、1分超は残り時間」と言っている。DELVERS の派遣は10〜480分なので
残り時間が主役で正しい。ただし**「あと何分」の粒度が粗い**（`coarseDuration`）ので、
残り1分を切ったときの見え方を確かめていない。

### C で4点引いた理由

**シミュレータで通知を実際に受け取っていない。** 直したのは
「予約する・前景でも出す・許可を毎回訊く」という**経路**であって、
「実機で本当に鳴った」ことは確認していない。
`nil` トリガーの時も、コードは一見正しく見えていた。
経路が繋がっていることと、届くことは別。

## このラウンドで、検査そのものの欠陥が3つ出た

**すべて「通っていたのに、見ていなかった」形。**

1. **A3 が `isHittable` で絞っていた。** 当たり判定が壊れた要素は false を返すので、
   **44pt を満たさない要素だけが 44pt の検査から除外される**構造になっていた。
   一番小さいものを見ずに満点を出していた。
2. **変異の当て先を間違えた。** 「枠の端を押す」検査を `cta` に当てたが、
   あれは背景を持つので `contentShape` が無くても押せる。捕まらなくて当然だった。
3. **`isHittable` は被さりを見ない。** 地図のノードは板の下でタップを飲まれていたのに
   10個とも「押せる」と報告されていた。拠点のチップで一度踏んだ穴と同じ。

→ **寸法を測るのをやめて、押して、変わったかを見る**検査に置き換えた。
